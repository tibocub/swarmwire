# Tasks: Peer Events, Counts and Folder File List

**Input**: Design documents in `specs/002-peer-events-file-list/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/api.md, quickstart.md

**Tests**: Included and written first. Constitution Principle IV requires test-first for transfer logic and a `test/swarm/` test for every resilience claim.

**Format**: `- [ ] T### [P?] [US#?] Description with file path`. `[P]` means a different file with no dependency on an unfinished task.

Decisions already made (do not reopen): no wire change (a serving node sends the ordinary `want`); the list reader is look-only and in memory; `Swarmwire` becomes an `EventEmitter` with events `peer-connected` and `peer-disconnected` carrying `{ id }`; the new API is `peerCount`, `counts(link)`, `readList(link)` and `downloadFile(link, file, outPath)`; nothing new is exported from `index.js`; version 0.2.0. Names and shapes are in `contracts/api.md`.

Reminder for every task touching `lib/`: no `Buffer`, no `node:` imports, no new globals (Bare). `lib/swarmwire.js` is already 841 lines: put new logic in `lib/holdings.js` (store, watch set, counting) and `lib/listing.js` (the reader and its in-memory destination), and keep edits to `swarmwire.js` to calls into them.
